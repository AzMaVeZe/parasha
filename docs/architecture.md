# מבנה

## עיקרון

אתר סטטי בלי שלב בנייה ובלי תלויות ריצה. HTML, CSS ו-JavaScript רגיל. כל מה שדורש שרת — דיוור ותגובות — יושב ב-Worker אחד.

הסיבה: הארכיון הזה צריך לשרוד שנים בלי תחזוקה. כל תלות היא דבר שיישבר מתישהו.

## האתר

```
index.html          עמוד יחיד. שני <main>: הארכיון ועמוד הדף הבודד
styles.css          נקודת כניסה יחידה, מייבאת את tokens/
tokens/             משתני עיצוב: צבעים, טיפוגרפיה, מרווחים, אפקטים
js/data.js          הנתונים: 62 פרשות וחגים, קישורי PDF ופודקאסט
js/riddles.js       החידות (נוצר מ-scripts/riddles-source/)
js/site.js          כל ההתנהגות
js/pdf-manifest.js  רשימת ה-PDF הקיימים (נוצר מסקריפט)
assets/             pdfs, previews, riddles, fonts, icons, audio
_headers            כותרות HTTP ל-Cloudflare Pages
dist/p/<שם>/        עמוד סטטי לכל דף — נוצר בבנייה, לא בגיט
dist/sitemap.xml    מפת האתר — נוצרת בבנייה
dist/llms.txt       תיאור האתר למערכות AI — נוצר בבנייה
```

**ניתוב:** מבוסס hash. `#p=<שם הפרשה>` פותח את עמוד הדף, כל דבר אחר מציג את הארכיון. אין שרת שמנתב, ולכן אין 404 ואין הגדרות rewrite.

**למה יש גם עמודים סטטיים:** מנוע חיפוש אינו רואה מקטע כתובת (`#p=…`) כעמוד נפרד — כל 62 הדפים היו תוצאה אחת. `scripts/build-pages.js` מייצר מ-`js/data.js` עמוד HTML אמיתי לכל דף תחת `/p/<שם>/`, עם כותרת, תיאור, canonical, Open Graph ו-JSON-LD משלו, קישור ל-PDF, נגן הפודקאסט אם יש והחידה שבדף. הכרטיסים בארכיון מצביעים על הכתובות האלה, אבל לחיצה מיורטת ב-`js/site.js` ונשארת בתוך האתר — כך שהחוויה לא השתנתה, וגם `#p=<שם>` הישן (שנשלח במיילים במשך שנים) ממשיך לעבוד בדיוק כשהיה.

השם בכתובת הוא השם העברי, מקודד ב-percent: גרשיים יורדים ורווח הופך למקף, כמו בשמות קבצי ה-PDF (`ט"ו באב` ← `/p/טו-באב/`). דף בלי PDF (יום כיפור) נוצר גם הוא, אבל מסומן `noindex` ואינו במפת האתר — אין בו תוכן לאנדקס.

**מדוע מניפסט ולא בדיקה חיה:** האתר צריך לדעת אילו קבצי PDF קיימים כדי להציג כפתור "צפייה". בדיקה חיה הייתה דורשת 55 בקשות HEAD בכל טעינה. במקום זה `scripts/build-pdf-manifest.sh` מייצר רשימה סטטית.

**תצוגה מקדימה:** `assets/previews/*.jpg` — העמוד הראשון של כל דף, מרונדר מראש. הניסיון הראשון היה `<iframe>` עם ה-PDF, אבל אנדרואיד לא רינדר אותו ו-iOS לא מירכז אותו.

## השרת

Worker אחד ב-`worker/src/index.js`, עם KV אחד.

| נתיב | מה עושה |
|---|---|
| `POST /subscribe` | הרשמה לדיוור, שולח מייל אישור (double opt-in) |
| `GET /confirm` | אישור ההרשמה מתוך המייל |
| `GET /unsubscribe` | הסרה (גם One-Click לפי תקן) |
| `POST /comments` | שליחת תגובה; נכנסת כ"ממתינה" |
| `GET /comments` | התגובות המאושרות, או מפת מונים לכרטיסים |
| `GET /moderate` | אישור/דחייה מתוך המייל |
| `GET /admin` | דף ניהול תגובות בעברית |
| `GET /status` | אבחון: מפתחות, דומיינים ב-Resend, נרשמים |
| `GET /testmail` | שליחת מייל בדיקה, מחזיר את תשובת Resend כמות שהיא |
| cron | שני/חמישי/שישי 04:00 UTC — שולח את דף השבת הקרובה |

**מפתחות ב-KV:**

```
sub:<email>        נרשם לדיוור
capp:<parasha>     מערך התגובות המאושרות — מה שהאתר קורא
cpend:<id>         תגובה הממתינה לאישור
cindex             { "<פרשה>": <מספר> } למוני הכרטיסים
crate:<ip>         מונה הגבלת קצב, פג אחרי 5 דקות
```

**פרטיות התגובות:** כתובת המייל של המגיב נשמרת רק ב-`cpend:` ובדף הניהול. `capp:` ו-`cindex` — מה שהדפדפן קורא — לא מכילים אותה כלל. זו הגנה מבנית, לא זהירות תפעולית.

## נראות בחיפוש וב-AI

`robots.txt` מתיר הכול, ומונה במפורש בשמם את זחלני ה-AI (GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot ואחרים) — כדי שיהיה ברור מה הותר, ולא רק "מותר לכולם". `sitemap.xml` מונה 64 כתובות: הבית, `/p/`, 61 עמודי דף והצהרת הנגישות.

`llms.txt` נוצר גם הוא. חשוב לדעת: זו הצעה שאינה תקן, וזחלני החיפוש הגדולים כמעט אינם קוראים אותה בפועל (סדר גודל של מאות פניות מתוך מאות מיליוני ביקורי בוטים). הוא נשאר כאן כי הוא זול ומדויק — לא כי הוא צפוי להביא תנועה.

הנתונים המובנים (JSON-LD) בנויים סביב שלושה מזהים קבועים — `#website`, `#author`, `#podcast` — שחוזרים בכל עמוד וקושרים הכול לישות אחת. הם מוגדרים ידנית ב-`index.html` ומיוצרים ב-`scripts/build-pages.js`; **שינוי באחד מחייב שינוי בשני.** בלוק `<script type="application/ld+json">` הוא נתונים ולא קוד, ולכן `script-src 'self'` אינו חוסם אותו (נבדק בדפדפן).

## נתונים חיצוניים

**Hebcal** (`connect-src` ב-CSP) — איזו פרשה או חג קרובים, לפי לוח ישראל (`il=on`). גם האתר וגם ה-Worker שואלים אותו, כל אחד בנפרד.

התאמת השמות בין Hebcal לאתר דורשת נרמול: הסרת ניקוד וטעמים, אבל **לא** את המקף העברי (U+05BE), אחרת "ניצבים־וילך" נשבר. ההתאמה מדויקת בלבד, עם טבלת כינויים (`שפטים`→`שופטים`, `סכות`→`סוכות`) — התאמה חלקית תפסה בעבר את "בא" מתוך "תשעה באב".

**Resend** — שליחת מיילים מ-`parasha@azma.app`. הדומיין `azma.app` מאומת שם.

## אבטחה

CSP מוגדר בשלושה מקומות: תגית `<meta>` ב-`index.html`, קבוע `CSP` ב-`scripts/build-pages.js` (נכנס לכל עמוד ב-`/p/`), וכותרת אמיתית ב-`_headers`. **שלושתם חייבים להישאר תואמים** — הדפדפן אוכף את המחמירה מבין השתיים, ואי-התאמה תחסום משהו בלי אזהרה.

`frame-ancestors` קיים רק בכותרת (תגית `<meta>` לא יכולה לבטא אותו) והוא `'self'` — ראו [`incidents.md`](incidents.md).

הגופנים מתארחים מקומית ולא נטענים מגוגל: גם בשביל הפרטיות של הקוראים וגם כדי ש-`font-src 'self'` יישאר אפשרי.
