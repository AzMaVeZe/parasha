# ספר הפעלה

## להוסיף דף חדש

1. לשים את ה-PDF ב-`assets/pdfs/` בשם `<ספר>-<פרשה>.pdf` (למשל `devarim-ראה.pdf`)
2. `bash scripts/build-pdf-manifest.sh` — מעדכן את רשימת הקבצים הקיימים
3. `python3 scripts/build-previews.py` — מרנדר את העמוד הראשון לתצוגה מקדימה
4. `node scripts/build-parashot-json.js` — מעדכן את המפתח שה-Worker קורא לדיוור
5. לוודא שיש רשומה מתאימה ב-`js/data.js` עם `pdf: P('...')`
6. commit + push. Cloudflare פורס תוך פחות מדקה.

עמוד הדף הסטטי (`/p/<שם>/`), מפת האתר ו-`llms.txt` נוצרים מחדש בכל בנייה מתוך
`js/data.js` — אין מה לעדכן ידנית, ואין קובץ `sitemap.xml` בריפו. לבדיקה מקומית:

```bash
bash scripts/build-site.sh && cd dist && python3 -m http.server 8000
```

הבנייה נכשלת אם מספר העמודים שנוצרו אינו תואם למספר הדפים ב-`js/data.js`.

הכפתורים "צפייה"/"הורדה" מופיעים רק כשהקובץ באמת קיים במניפסט, ולכן אפשר להוסיף בהדרגה.

## להוסיף פודקאסט

ב-`js/data.js`, להוסיף לשורה של הפרשה:

```js
spotify: 'https://open.spotify.com/episode/XXXXXXXX'
```

בלי הפרמטר `?si=...` — הוא מזהה מעקב, ואינו נחוץ. הנגן והתגית "פודקאסט" בכרטיס מופיעים אוטומטית.

## לאשר תגובה

תגובה חדשה שולחת מייל ל-`OWNER_EMAIL` עם כפתורי **אישור ופרסום** / **דחייה**. אפשר גם:

```
https://parasha-newsletter.azma.workers.dev/admin?key=<ADMIN_KEY>
```

רשימה של הממתינות ושל המפורסמות, עם כפתור הסרה לכל אחת. שום תגובה לא מופיעה באתר לפני אישור.

## דיוור

רץ אוטומטית שני/חמישי/שישי ב-04:00 UTC (07:00 שעון קיץ). כל נרשם מקבל רק ביום שבחר. שליחה ידנית:

```
https://parasha-newsletter.azma.workers.dev/send?day=mon&key=<ADMIN_KEY>
```

המייל כולל עד שני כרטיסים — החג הקרוב ופרשת השבת — כל אחד עם קישור לדף ולפודקאסט אם יש. דף בלי PDF לא נשלח, ואם אין שום דף מתאים המייל לא יוצא בכלל.

## להחליף גופן

לערוך את `FAMILIES` ב-`scripts/build-fonts.py` ולהריץ את ה-Action **"עדכון גופנים"** (Actions ‹ Run workflow). הוא מוריד, כותב את `fonts.css`, מוחק קבצים שיצאו משימוש, ודוחף. אם משהו חסר — הוא נכשל ולא דוחף.

## פרק פודקאסט חדש

הפרקים נוצרים כסקירה קולית ב-NotebookLM, במחברת "פרשת השבוע" שבה כל הדפים:
מסמנים רק את הדף של השבוע, ושני מנחים דנים ברעיונות שבו. `scripts/make-episode.py`
עושה את זה מהמחשב של אריאל (NotebookLM חסום מסביבת Claude), ומכין תיקייה להעלאה:

```
python scripts/make-episode.py "לך לך"               # פרשה אחת
python scripts/make-episode.py --from "לך לך" --count 3
python scripts/make-episode.py --book שמות           # כל ספר, רק פרשות בלי פרק באתר
python scripts/make-episode.py --sources             # המקורות שבמחברת
```

סקירה שכבר נוצרה במחברת (ביד, ב-Studio) לא נוצרת שוב — מורידים אותה. הסקריפט
מזהה את הפרשה לפי כותרת הסקירה או לפי הבקשה שממנה נוצרה; כשאין התאמה אחת ויחידה
הוא מציג את האפשרויות ומדלג, ומריצים שוב עם `--artifact <id>`:

```
python scripts/make-episode.py --audio                     # הסקירות שבמחברת, ולאיזו פרשה
python scripts/make-episode.py --existing --book בראשית
python scripts/make-episode.py --existing "לך לך" --artifact <id>
```

בתיקייה `scripts/episodes/` (או `--out`), שלושה קבצים לכל דף ששמם מתחיל בשם הפרשה:
קובץ השמע, `- כרטיס.png`, ו-`- תיאור.txt` עם הכותרת והתיאור, כולל הקישור לעמוד
הדף. מעלים ל-Spotify for Creators, שומעים לפני
פרסום, ושולחים ל-Claude את קישור הפרק כדי שייכנס ל-`js/data.js`. התיקייה מחוץ ל-git.
יש מכסה יומית לסקירות קוליות: כשהיא נגמרת הסקריפט עוצר, ולמחרת ממשיכים.

## תמונת שער לפרק

כרטיסי הפרקים בספוטיפיי הם ריבוע בעיצוב אחיד: קרם למעלה (פרשת השבוע, תגית הספר,
כותרת, פסוק הפתיחה עם פס זהב) ופאנל כחול למטה (שם הכותב והשנה).
`scripts/make-covers.mjs` מייצר אותם, והקבצים נשמרים ב-`assets/covers/` ב-3000×3000.

יש כרטיס לכל דף שב-`js/data.js`. אחרי דף חדש: `node scripts/make-covers.mjs` (נדרש `playwright`).
הפסוק והשנה נלקחים מ-`scripts/sheets.mjs`, אותו מקור של תמונות השיתוף.

`LINES` בסקריפט — משפט אופציונלי לפאנל הכחול: משפט מפתח או תמיהה מהדף, או שאלה שנוסחה לפי התוכן.
נכנס רק אחרי אישור של אריאל. בלעדיו הפאנל מציג את שם הסדרה.

לעריכה ויזואלית: `node scripts/make-covers.mjs --dc <תיקייה>` מפיק לוחות עבור Claude Design.
הכיתוב נכתב ב-HTML ולא בתוך איור, כי מודלי תמונה משבשים עברית.

## תמונת שיתוף (ווטסאפ)

כששולחים קישור בווטסאפ, ווטסאפ מציג את התמונה שב-`og:image` של העמוד. `scripts/make-share.mjs`
מייצר את כולן ב-1200×630, באותו עיצוב של כרטיסי הפודקאסט בפריסה רוחבית:

- `assets/og-image.jpg` — לאתר כולו (דף הבית, `/p/`)
- `assets/share/<שם>.jpg` — לכל פרשה וחג: מימין שם הפרשה, פסוק הפתיחה והשנה שבכותרת הדף;
  משמאל העמוד הראשון של הדף. הפסוק והשנה נמצאים ב-`scripts/sheets.mjs`.

אחרי שמוסיפים דף חדש: להוסיף אותו ל-`scripts/sheets.mjs`, להריץ `node scripts/make-share.mjs`, ואז בנייה. הכתובת
בעמוד כוללת `?v=` לפי תוכן הקובץ, כך שווטסאפ טוען מחדש תמונה שהוחלפה.

כפתור "שיתוף" בראש כל עמוד דף שולח את הכתובת הסטטית `/p/<שם>/` ולא `#p=`, כי ווטסאפ לא
רואה מה שאחרי `#`. רק כך מגיעה התמונה של הפרשה. בתצוגה המקדימה ווטסאפ שומר תמונה במטמון:
קישור שכבר נשלח לפני השינוי ימשיך להציג את הישנה.

## מקורות מספריא

בעמוד של דף שהמקורות שלו נבדקו יש תיבה מתקפלת "מקורות": המקורות שהדף מצטט, לפי סדר
הופעתם, בנוסח ספריא ועם קישור לכל אחד. מראי המקום שבתוך "קריאת הדף כטקסט" הופכים
לקישורים. ה-API של ספריא לקריאה פתוח ואינו דורש מפתח.

```
python3 scripts/sefaria-sources.py find bamidbar-בהעלותך   # הצעה אוטומטית ← scripts/sources/
python3 scripts/sefaria-sources.py fetch                   # הנוסח מספריא ← assets/sources/ ו-js/sources-manifest.js
```

`find` נכון בערך בארבעה מקורות מתוך חמישה: הוא מפספס מקורות, מזהה פירוש במקום המקור
עצמו, ומסמן הפניה כללית ("בפרשת פנחס") כמקור. לכן מה שהוא כותב ל-`scripts/sources/`
הוא טיוטה שבודקים ביד, ו-`find` לא דורס קובץ שכבר קיים שם. ב-`scripts/sources/<שם>.json`
כל מקור הוא `ref` (בשם האנגלי של ספריא), `para` (מספר הפסקה בטקסט שחולץ) או `fn` (מספר ההערה ברשימת הערות השוליים), ו-`anchor`
אופציונלי: מראה המקום כפי שהוא כתוב בפסקה, שהופך לקישור. מקור נכנס כשהדף מצטט אותו;
הפניה בלבד ("מופיע גם בירושלמי") לא נכנסת.

הנוסח עובר בדרך: טעמי המקרא יורדים, הניקוד נשאר, ושם ה' נכתב ה׳, כמו בדפים. ליד כל
מקור מופיעים שם הנוסח והרישיון שלו בספריא. רוב נוסחי התלמוד והמדרש שם הם CC-BY-NC:
מותר באתר, שאינו מסחרי, אבל **לא בספר שנמכר**.

### דיווח לספריא (Linker)

כדי שהדפים יופיעו בספריא ב"דפי אינטרנט" שמצטטים כל מקור, רץ ה-Linker של ספריא (v3) — **רק על
רשימת המקורות שנבדקו**, ובלי ליצור קישורים. בעמוד הדף עצמו הוא היה סורק גם את "קריאת הדף כטקסט"
ומדווח על זיהויים שגויים, ולכן:

- `scripts/build-pages.js` מייצר לכל דף עם מקורות את `p/<שם>/sources.html`: רשימת ה-refs באנגלית,
  שספריא מזהה במדויק, עם `canonical` לעמוד הדף — כך הדיווח הוא על עמוד הדף. העמוד `noindex`.
- עמוד הדף טוען אותו ב-iframe נסתר אחרי שהטעינה הסתיימה (`js/sefaria-report.js`), ושם
  `js/sefaria-linker.js` טוען את `https://www.sefaria.org/linker.v3.js`.
- ל-`sources.html` יש **CSP צר משלו** שמתיר את `www.sefaria.org`: ב-`_headers` (כלל
  `/p/:name/sources.html`, שמסיר את ה-CSP הכללי ומחליף אותו) ובתגית ה-`<meta>` של העמוד
  (`SOURCES_CSP`). הבנייה נכשלת אם השניים נפרדים. ה-CSP של שאר האתר לא השתנה.
- ה-Linker מבקש גם גופן מ-Google Fonts (לחלונית שאינה בשימוש כאן); ה-CSP חוסם אותו, וזו שגיאה
  שקטה בקונסול של ה-iframe.
- ספריא מציגה דף אינטרנט רק לאחר שהאתר מוכר אצלה; `api/websites/parasha.azma.app` מחזיר כיום "no
  website found". אם הדפים לא מופיעים אחרי כמה שבועות — לפנות לספריא ולבקש לרשום את הדומיין.

## סטטיסטיקת ביקורים

Cloudflare Web Analytics: ביקורים, עמודים, מדינות וסוג מכשיר, בלי עוגיות. גלוי רק בחשבון
Cloudflare. הקוד ב-`js/analytics.js`, ונטען בכל עמוד. פעיל מאוקטובר 2026.

הפעלה (פעם אחת):
1. dash.cloudflare.com ‹ **Analytics & Logs** ‹ **Web Analytics** ‹ **Add a site**
2. Hostname: `parasha.azma.app`, ואז **Done**. אם נשאלים — לבחור בהתקנה ידנית (JS snippet), לא אוטומטית
3. מהקטע שמוצג להעתיק את הערך של `"token"` ולשים אותו ב-`TOKEN` שב-`js/analytics.js`

ה-CSP מתיר את `static.cloudflareinsights.com` (הסקריפט) ואת `cloudflareinsights.com` (שליחת
הנתונים) בכל ארבעת המקומות שבהם הוא מוגדר; הבנייה נכשלת אם אחד מהם שוכח. הצהרת הנגישות
מזכירה את הספירה בסעיף הפרטיות.

## כשמשהו לא עובד

**סדר הבדיקה, מהזול ליקר:**

1. `https://<worker>/status?key=<ADMIN_KEY>` — מפתחות, כתובות, סטטוס הדומיין ב-Resend, נרשמים, מוני תגובות,
   ו-`sends`: עשר השליחות האחרונות — מתי, אילו דפים, כמה נשלחו, כמה נכשלו ולמה
2. `https://<worker>/testmail?to=<כתובת>&key=<ADMIN_KEY>` — מנסה לשלוח באמת ומחזיר את שגיאת Resend מילה במילה
3. `https://parasha.azma.app/js/data.js?nocache=1` — לוודא איזו גרסה מוגשת בפועל. פרמטר שונה בכל פעם, אחרת הדפדפן מגיש מהמטמון
4. `npx wrangler tail` — לוגים חיים מה-Worker

**"משהו השתבש בשליחה"** — כמעט תמיד הדומיין לא מאומת ב-Resend. `/status` מציג `fromDomainVerified`.

**האתר לא מתעדכן** — לבדוק שהפריסה ב-Cloudflare באמת עברה, ולוודא מול `?nocache=` איזו גרסה מוגשת. אל תניח שזה מטמון בדפדפן לפני שווידאת.

## הגדרות שצריך לשמור עליהן

**Cloudflare Pages** — Build command `bash scripts/build-site.sh`, Build output directory `dist`. בלי זה מוגש כל הריפו.

**GoDaddy DNS** — הרשומה `parasha` היא CNAME. **אסור** ליצור רשומה כלשהי שנגמרת ב-`.parasha` — DNS אוסר על רשומות-בת מתחת ל-CNAME, וזה מפיל את האתר לגמרי. רשומות Resend יושבות על השורש (`send`, `resend._domainkey`, `_dmarc`).
